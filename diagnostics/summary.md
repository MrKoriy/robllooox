# summary.md — краткий вывод

## 1. Что работает на текущей сборке и чем подтверждено
- **pcall-hook deferred-exec** (новый путь, этот diff): staged wire-чанк исполняется inline на живом игровом треде в момент его luaB_pcall. Подтверждено сериями rc=0 (fires=400+) и матрицей R1–R7 (см. repro-matrix).
- **Запись свойств работает** (`game.Workspace.Gravity = 50` → rc=0, дважды, клиент жив) — исторический write-barrier exec-пути в этом контексте снят. Подтверждение: repro-matrix R7 + лог.
- Чтения, арифметика (MUL/MULK/ADD/ADDK/POWK — wire-опкоды выведены из дизасма хендлеров и проверены семантическими пробами), строки, замыкания, namecall — всё rc=0.
- Трамплин: fixed-frame вариант доказан изолированным тестом (85/85, 2 вызова). Stale-hook recovery проверен вживую (re-point чужого патча без краша).
- Сборка/тесты: `make clean && make` exit 0; smoke 5/5; resolvetest PASS (логи приложены).

## 2. Самый маленький вход, воспроизводящий сбой
- Активный дефект: `repro/r8_pulse_fails_load.lua` (много-стейтментный чанк) → «bytecode corrupted» при загрузке, rc=-21, без краша. Фрагменты по одному — грузятся.
- Падение (остаточное, недетерминированное): см. crash/ — через ~13с после успешного fire, в luaB_pcall с L=NULL.

## 3. Где впервые нарушается проверяемый инвариант
- Для R8: на этапе wire-ремaпа (вне процесса) — вероятная рассинхрон aux-разметки (AUX_OPS vs getOpLength); первый нарушенный инвариант — «ncode-выравненный обход кода». Доказать точкой рассинхрона — следующий шаг.
- Для падения 52574: первое видимое нарушение — thread==NULL при входе в luaB_pcall спустя 13с после нашего fire (инвариант «x0=L≠NULL»).

## 4. Что исключено / что остаётся
- Исключено: «трамплин ломает регистры» (изолированный тест), «write-barrier непреодолим» (hook-путь пишет), «резолвер не находит символы» (PASS), «смешение версий» (UUID/версия зафиксированы), «стак патчей» (recovery + тест).
- Остаётся: H2 (отложенная порча треда — главный остаточный риск), H3 (aux-разметка ремаппера), точный механизм исторического NULL-диспатча на exec-пути (академически — hook-путь его обходит).

## 5. Следующая проверка с максимумом информации
**lldb-наблюдение за тредом сразу после rc=0-fire**: снять CallInfo-цепочку и флаги треда и сравнить с девственным — однозначно подтверждает/опровергает H2. Далее: довывод aux-таблицы из getOpLength → починка R8 → fly-пульс целиком.
